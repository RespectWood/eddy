## Implementation notes (2026-10-22)

Changes from the plan below, decided while building:

- **Odesli is gone.** Its keyless API returns `401 PUBLIC_API_ACCESS_DEPRECATED`. Replaced by:
  - Spotify metadata from the public embed page (`open.spotify.com/embed/…`): title, artists, duration, explicit flag. No credentials, but unofficial and could change.
  - **Apple Music:** iTunes Search API + fuzzy matching (title, artist, duration, explicit, track count). Albums fall back to song search, because album search leaves out some major albums.
  - **Tidal:** ISRC/UPC from Deezer's public API, then the official TIDAL API (`openapi.tidal.com/v2`, client credentials). **Needs a free developer.tidal.com app.** Without credentials, Tidal opens a search for "artist title". TIDAL API calls verified on 2026-10-22 with a development-mode app: Blinding Lights → `tidal://track/136204275`.
  - Deezer doesn't always return the original release's ISRC (e.g. a 2006 reissue instead of 1987), so Tidal may open a different release of the same song.
- **Tidal deep links** (checked against TIDAL 2.43.2's source): `tidal://track/<id>`, `tidal://album/<id>`, `tidal://search?q=a+b`. The app runs `encodeURI` over the link, so search queries are ASCII with `+` for spaces (accents transliterated). Tidal queues a link that launched it, so Eddy sends the link exactly once. An earlier extra resend froze Tidal on cold start.
- **No Xcode project:** this machine only has the Command Line Tools, so the app is a **SwiftPM package** (`macos/`) and `scripts/build-app.sh` builds the `.app` bundle, signs it and zips it. Universal (arm64 + x86_64) builds work without Xcode.
- **Blocking Rust API instead of async:** `Resolver.resolve` is a blocking call (`ureq`) that Swift runs on a background task. That's simpler than an async runtime across FFI.
- **`spotify:` scheme:** declared in Info.plist, but Eddy doesn't take it over from an installed Spotify app.
- **Bundle ID** `com.respectwood.eddy` is a placeholder until there's a domain.
- **Not done (needs you):** Developer ID signing + notarization (`SIGN_IDENTITY` / `NOTARY_PROFILE` in `build-app.sh`), the GitHub release, the `v0.1.0-alpha` tag, and the [manual tests](../manual-tests.md).

## Goal

Get from an empty repo to a **working v0.1 alpha** that a handful of testers (us and friends) can use every day:

> A friend sends a Spotify track link in Messages or Slack. I click it. The track opens in my Tidal (or Apple Music) **desktop app**. Every other link I click opens in my normal browser as before.

This ticket covers the whole path through the plan's architecture (Rust core → UniFFI → Swift menu bar shell), so every layer exists and works together. Later tickets make each layer more robust.

## Definition of done (v0.1 alpha)

- [ ] **Launch:** opening `Eddy.app` adds an icon to the **top menu bar**. There's no Dock icon and no window. See PLAN.md §3 "Menu bar presence".
- [ ] **Onboarding:** on first launch, the user picks a preferred service (Apple Music / Tidal) and a real browser (any installed browser other than Eddy). Then Eddy registers itself as the system's web link handler. macOS calls this the "default web browser" and shows a confirmation dialog for it. Eddy isn't a browser: it only receives each clicked link, handles Spotify links, and immediately passes every other link to the user's real browser (same approach as Velja and Finicky).
- [ ] **Pass-through:** ordinary links open in the chosen real browser with no noticeable delay: < 50 ms, no network calls.
- [ ] **Spotify track and album links** (including `?si=`, `intl-xx`, `spotify:` links and `spotify.link` / `spoti.fi` short links) open the matching item in the **native desktop app** when it's installed. The web player is used only when the app isn't installed.
- [ ] **Not found:** if there's no match, the target app opens a search for "artist title" and a notification explains what happened.
- [ ] **Other Spotify links** (playlist, episode, show, artist) are passed to the real browser unchanged. Artist links get converted in a later ticket.
- [ ] **Menu:** status line, Pause/Resume, last 10 conversions (click to open again, "Open original link"), preferred service, real browser, Launch at login, Quit.
- [ ] **Signing:** built with Developer ID and notarized, or at minimum ad-hoc signed with documented steps for alpha testers to open it.
- [ ] **Release:** `v0.1.0-alpha` git tag, plus a zipped `.app` attached to a GitHub release (draft is fine).
- [ ] **Tests:** CI is green, and the manual test checklist at the bottom of this ticket has been run.

## Work breakdown

Each milestone can be merged on its own and keeps `main` green.

### M1 — Rust workspace + Spotify link parser (1–2 days)

**Workspace**
- Root `Cargo.toml` workspace (`resolver = "2"`, shared `[workspace.package]`: edition 2021, `license = "MIT OR Apache-2.0"`, repository), plus shared lints.
- `rust-toolchain.toml` pinned to `stable`, with `rustfmt` and `clippy`.
- Crates: `crates/eddy-core` (library) and `crates/eddy-cli` (binary `eddy`).

**`eddy-core::link`.** Names can change in review.

```rust
pub enum SpotifyKind { Track, Album, Artist, Playlist, Episode, Show }

pub struct SpotifyLink {
    pub kind: SpotifyKind,
    pub id: String,           // base62, 22 chars
}

pub enum ParsedLink {
    Spotify(SpotifyLink),
    SpotifyShortLink(Url),    // needs network expansion
    NotMusic,
}

/// Sync, no I/O. Called for every clicked URL.
pub fn parse(url: &str) -> ParsedLink;
pub fn is_music_link(url: &str) -> bool;

impl SpotifyLink {
    pub fn canonical_url(&self) -> String;   // https://open.spotify.com/{kind}/{id}
    pub fn uri(&self) -> String;             // spotify:{kind}:{id}
}
```

Must handle:
- [ ] `https://open.spotify.com/{track|album|artist|playlist|episode|show}/{id}`
- [ ] Query and fragment removed (`?si=…`, `?context=…`, `#…`)
- [ ] Locale prefix: `intl-xx` / `intl-xx-YY`
- [ ] `http://`, a trailing slash, uppercase host, old host `play.spotify.com`
- [ ] URI scheme: `spotify:track:{id}`, and the older `spotify:user:{user}:playlist:{id}`
- [ ] Short links `spotify.link/*`, `spoti.fi/*` → `SpotifyShortLink`
- [ ] Everything else → `NotMusic`, including look-alike hosts (`open.spotify.com.evil.tld`), invalid IDs and `/user/…` pages

**CLI:** `eddy parse <url>` prints JSON.

**Tests:** table-driven tests for every case, a fixture corpus `tests/fixtures/links.txt`, and a test that `parse()` takes well under 1 ms.

**CI:** `.github/workflows/ci.yml` on `macos-latest` runs `cargo fmt --check`, `cargo clippy -- -D warnings` and `cargo test`.

### M2 — Resolver: Odesli + short links + cache (2–3 days) — *replaced, see implementation notes*
- `expand` module: follow redirects for `spotify.link` / `spoti.fi` (HEAD, falling back to GET, 3 s timeout, max 5 redirects) and parse the result.
- `Resolver` trait plus `OdesliResolver` (`api.song.link/v1-alpha.1/links?url=…&userCountry=…`). Returns the target service's ID and URL, plus title/artist for the search fallback.
- `CacheResolver`: SQLite (`rusqlite`, bundled) in `~/Library/Application Support/eddy/cache.sqlite`, keyed by `(spotify_kind, spotify_id, target_service, storefront)`.
- `target` module: builds deep links for each service:
  - Apple Music: `music://music.apple.com/{storefront}/song/{id}` (also album)
  - Tidal: `tidal://track/{id}`, `tidal://album/{id}`. **Check these formats against the Tidal desktop app.**
  - web fallback URLs and search URLs for both services
- Errors are typed (`NotFound`, `RateLimited`, `Network`, `Unsupported`) so the shell can choose the right fallback.
- CLI: `eddy resolve <url> --to tidal|apple-music [--country DE]`.
- Network-dependent tests run behind `--ignored` / a feature flag. Unit tests use recorded Odesli responses.

### M3 — UniFFI bindings + Swift package (1–2 days)
- `crates/eddy-ffi` exposes `is_music_link` (sync), `parse` (sync) and `resolve` (async) through UniFFI proc-macros.
- `scripts/build-xcframework.sh` builds for `aarch64-apple-darwin` and `x86_64-apple-darwin`, joins them with `lipo` into a universal library, generates the Swift bindings and packages an `.xcframework` that the Xcode project uses.
- Generated files go in `macos/Generated/` (gitignored). The script is run from an Xcode build phase, or by hand.

### M4 — Swift menu bar shell (4–6 days)
- `macos/eddy.xcodeproj`: SwiftUI app, macOS 13+, `LSUIElement = YES`, `MenuBarExtra` with a template-image icon.
- **Info.plist:** `CFBundleURLTypes` (`http`, `https`, `spotify`) and `CFBundleDocumentTypes` (`public.html`, `public.url`), so the app counts as a browser.
- **URLRouter:** receives URLs from the system (`kAEGetURL` Apple Event handler / `application(_:open:)`) → `is_music_link` → either `BrowserForwarder` or the resolve flow.
- **BrowserForwarder:** `NSWorkspace.open(_:withApplicationAt:configuration:)` with the chosen real browser. Never sends a link back to Eddy itself.
- **AppOpener:** finds installed apps (`urlForApplication(withBundleIdentifier:)` / `urlForApplication(toOpen:)`) and opens the **native app first**, the web player only as a fallback. It handles a cold start: launch the app, wait until it's ready, send the deep link, and retry once.
- **Onboarding window** (shown only on first run or from the "Not active" menu item): pick the service, pick the browser, set the default browser (`NSWorkspace.setDefaultApplication(at:toOpenURLsWithScheme:)` on macOS 12+, otherwise point the user to System Settings).
- **Menu:** everything listed under Definition of done. Recent conversions are stored in `UserDefaults` or the core's SQLite database.
- **Launch at login:** `SMAppService.mainApp`.
- **Notifications:** `UserNotifications` for "not found" and "opened in web player because app isn't installed".

### M5 — Package and release the alpha (1 day)
- Version `0.1.0-alpha` in `Cargo.toml` and the Xcode project.
- Release build, signing and notarization (`notarytool`), zipped `.app`.
- `CHANGELOG.md` entry, `v0.1.0-alpha` tag, draft GitHub release with install notes for testers.

## Manual test checklist (before tagging)

The full, step-by-step version is in [docs/manual-tests.md](../manual-tests.md).

- [ ] Fresh install → menu bar icon appears, no Dock icon, onboarding runs
- [ ] Spotify track link clicked in **Messages**, **Slack**, **Discord**, **Mail**, **Notes** → opens in the native target app
- [ ] Same test with the target app **running**, **not running** and **not installed** (should fall back to the web player plus a notification)
- [ ] Short link (`spotify.link/…`) → converts correctly
- [ ] Album link → converts correctly
- [ ] Track that isn't on the target service → search opens plus a notification
- [ ] Playlist link → opens in the real browser unchanged
- [ ] 20 ordinary `https://` links → open in the real browser with no visible delay
- [ ] Pause → Spotify links go to the real browser; Resume → conversion works again
- [ ] Quit, then launch again → only one menu bar icon; launch at login works after a reboot
- [ ] Offline → ordinary links still work; Spotify links fall back gracefully

## Setup notes
- **Rust isn't installed on this machine yet:** `brew install rustup && rustup-init`, or https://rustup.rs. Add both macOS targets with `rustup target add aarch64-apple-darwin x86_64-apple-darwin`.
- **Xcode 15+** is required for M3–M5.
- **Apple Developer Program** membership is needed for Developer ID signing and notarization in M5.
- Odesli works without an API key for low volume (~10 req/min). That's enough for an alpha thanks to the cache. Request a key before a wider beta.
- Suggested crates: `url`, `serde`, `serde_json`, `reqwest` (rustls), `tokio`, `rusqlite` (bundled), `thiserror`, `uniffi`. `eddy-core::link` must stay free of I/O.
